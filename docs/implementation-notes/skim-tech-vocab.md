# Implementation notes, skim-tech-vocab

Only the delta from the brief: what was decided along the way, and why.

## Delta

- **Technical corpus: federal Markdown, not NIST or NASA PDFs.** The brief suggested NIST Special Publications and NASA technical reports. Those are PDFs, so the text would depend on the PDF extractor's version and the rebuild would stop being byte-identical. Instead the corpus is the Markdown of seven US federal documentation repositories (six GSA, one CMS), each pinned to a git revision. Each states that it is public domain in the US (17 U.S.C. 105) and also waives copyright worldwide under CC0 1.0, which is stronger than 17 U.S.C. 105 alone (that covers only the US). Two candidates were left out: `cfpb/design-system`, whose terms list third-party exceptions, and `CMSgov/design-system`, whose license starts with "A few parts of this project are not in the public domain".
- **Fetch.** `git fetch --depth 1 --filter=blob:none` of the pinned revision with a sparse checkout of `*.md`. A git revision is content-addressed, so no sha256 is needed for these rows; the manifest's `sha256` column became `hash` (a file sha256 or a git revision). The build now needs `git`.
- **Cleaning.** Each Markdown file loses its front matter, code fences, inline code, HTML, Liquid and Nunjucks tags, link targets and URLs before counting. License, contributing, security and changelog files are skipped, because their boilerplate repeats across repositories. Without that, `cc0`, `dedication` and `worldwide` ranked.
- **Agencies, not repositories.** The technical works are merged per agency (the last part of the contributors cell), so the technical corpus counts as two works. A word must appear in both agencies' docs to qualify through it, and a 4,000-token repository no longer outvotes a 190,000-token one. Six of the seven repositories are GSA; this keeps GSA house words out unless CMS uses them too. `18f` still ranks (462) because the CMS docs mention 18F; `uswds`, `gsa` and `fhir` do not.
- **Weight 0.3.** Tech weights 0.2, 0.3, 0.4 and 0.5 were measured (numbers in the proof file). 0.3 is the smallest that brings technical-doc coverage back to the level of the lists Skim shipped before #95: at or above it on six of seven samples, and 2 points under on the seventh (a 150-token page). At 0.3, fiction coverage falls about 2 points from main's literature-only lists and stays above the old lists.
- **Publication years from records, not recollection.** Each Gutenberg row's `published` is now the earliest year confirmed by its `evidence` cell. That cell holds a Library of Congress catalog record (LCCN, from the SRU catalog at `lx2.loc.gov`, matched on the plain imprint date and checked for title and author), or, for Carmilla and as a second source for Dracula, the dated title page in the hashed Gutenberg file. Wikidata was used only to find candidates. It was not cited, because it disagreed with the catalog at least once (朝花夕拾: 1932 there, 1929 at LoC).
- **Two works dropped**, with no LoC record dated 1929 or earlier and no dated title page: 野草 (Lu Xun, Gutenberg #25242) and 文明小史 (Li Boyuan, #25379). The Chinese corpus is now 11 works.
- **Weaker evidence, kept and labelled.** Some rows are confirmed by a record of the work, not of its first edition. For Treasure Island, a 1927 Yiddish translation; for Heart of Darkness, the 1902 collection Youth, whose record lists it; for Peter Pan, the 1911 Peter and Wendy; for The Federalist, an 1864 edition. Each still proves publication by 1929, the rule's only requirement. Some LoC imprints are approximate: `[1900?]` for The Sign of the Four, "between 1640 and 1644?" for 水滸傳.
- **Check.** `check-notices` (run by `skim-parity`) now also fails a row with an empty evidence cell, and a repository row that is not pinned to a full revision.
